# Termini per il glossario (Appendice B)

Raccolti capitolo per capitolo; la definizione finale si scrive nella sessione delle appendici.

| Termine | Capitolo | Definizione provvisoria |
|---|---|---|
| terminale | 6 | Finestra in cui si scrivono comandi testuali al computer |
| sessione | 6 | Una conversazione con Claude Code, dall'avvio all'uscita o a `/clear` |
| spinner | 6 | L'asterisco animato con il verbo in -ing che indica che Claude Code sta lavorando |
| slash command | 6 | Comando breve che inizia con `/`, per esempio `/help` |
| checkpoint | 6 | Punto della conversazione a cui si può tornare con `/rewind` |
| contesto | 6 | Tutto ciò che Claude Code ha «davanti» mentre lavora: conversazione, file letti, istruzioni |
| permesso | 6 | Conferma richiesta prima di un'azione che modifica file o esegue comandi |
| prompt | Pref. | La richiesta scritta che si dà a un modello o a Claude Code |
| breakpoint | 1 | Punto in cui si ferma un programma per esaminarne lo stato durante il debug |
| bug | 1 | Difetto di un programma |
| compilatore | 1 | Programma che traduce un testo leggibile da una persona nel linguaggio della macchina |
| shell | 1 | Interprete dei comandi: aspetta un comando, lo esegue, mostra il risultato |
| modello linguistico | 1 | Programma che ha imparato da molto testo a prevedere come continua una frase |
| Transformer | 1 | Architettura dei modelli linguistici moderni (2017) |
| agente | 1 | Programma che porta avanti un incarico da solo, a passi: guarda, decide, agisce, verifica |
| CLI | 2 | Command-line interface: programma che si usa scrivendo comandi nel terminale |
| container | 2 | Ambiente isolato, una specie di piccolo computer dentro il computer |
| linter | 2 | Programma che controlla il codice e segnala errori e problemi di stile |
| strumento (tool) | 2 | Azione che il programma intorno al modello esegue per lui: leggere, scrivere, eseguire comandi |
| product overhang | 2 | Quando un modello sa fare più di quanto i prodotti esistenti gli permettano |
| research preview | 3 | Anteprima di ricerca: versione dichiaratamente sperimentale di un prodotto |
| README | 3 | File di istruzioni che accompagna un programma o un progetto |
| repository | 3 | Archivio di un progetto con la storia di tutte le sue modifiche |
| commit | 3 | Fotografia del lavoro salvata nel repository con una descrizione |
| npm | 3 | Registro e gestore dei pacchetti JavaScript da cui si installano programmi |
| SDK | 3 | Kit per gli sviluppatori: strumenti per costruire altri programmi |
| changelog | 4 | Registro delle modifiche: elenco delle novità di ogni versione |
| versione (numero di) | 4 | Numero in tre parti (es. 2.1.318): grandi svolte, tappe importanti, piccoli aggiornamenti |
| plugin | 4 | Pacchetto installabile di comandi, agenti, hook e skill |
| marketplace | 4 | Catalogo da cui scegliere e installare i plugin |
| skill | 4 | Raccolta di istruzioni e conoscenze che Claude Code carica quando servono |
| hook | 4 | Regola automatica che scatta a un certo evento della sessione |
| sottoagente | 4 | Aiutante con un compito preciso e un contesto separato |
| sandbox | 4 | Recinto in cui i comandi girano isolati, con meno richieste di permesso |
| source map | 4 | File che collega il codice distribuito al codice sorgente originale |
| WSL | 4 | Windows Subsystem for Linux: un Linux che gira dentro Windows |
| PowerShell | 5 | La shell moderna di Windows |
| CMD (Prompt dei comandi) | 5 | La shell storica di Windows |
| PATH | 5 | Elenco delle cartelle in cui il sistema cerca i programmi da avviare |
| WinGet | 5 | Gestore di programmi di Windows (installa e aggiorna da riga di comando) |
| Homebrew | 5 | Gestore di programmi per macOS |
| Console (Anthropic) | 5 | Il sito per gli sviluppatori, con API e credito prepagato |
| plan mode | 7 | Modalità in cui Claude Code legge e ragiona senza modificare nulla, poi presenta un piano da approvare |
| prova a secco | 7 | Anteprima di un'operazione (per esempio una rinomina in blocco) prima di eseguirla davvero |
| criterio di «fatto» | 7 | Il modo in cui si verifica che un lavoro è finito e corretto; funziona da test |
| CLAUDE.md | 8 | File di istruzioni che Claude Code legge all'inizio di ogni sessione |
| Markdown | 8 | Formato di testo semplice: # per i titoli, - per gli elenchi |
| import (in CLAUDE.md) | 8 | Riga @percorso che fa leggere anche un altro file |
| memoria automatica | 8 | Note che Claude Code prende da solo tra una sessione e l'altra |
